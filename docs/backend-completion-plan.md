## 구현 결정

| 항목 | 최소 구현 | 완료 조건 |
|---|---|---|
| 콘텐츠 복구 | 서버가 검증한 승인자·실행자와 고정 대상·상태를 연결한다. 승인된 콘텐츠만 같은 트랜잭션으로 복구한다. | 권한·30일 기한·부모·삭제 작업·현재 소유권을 검사한다. 개별 삭제된 자식과 계정·관계·인증 상태를 복구하지 않는다. 실패는 전체 롤백한다. |
| 역이관 | 원 이관 결과의 프로젝트·version을 확인한다. 현재 유효한 권한으로 새 참여 기간과 새 이관 이력을 만든다. | 변경된 작업 공간·중복 관계·입력 변경을 거부한다. 기존 이력과 식별자를 보존한다. 같은 명령 재시도는 같은 결과를 반환한다. |
| 파일 처리 | 제공자 중립 저장 인터페이스와 명시적으로 설정한 로컬 어댑터를 구현한다. | 실제 바이트의 해시·크기를 검사한다. 객체 키를 재사용하지 않는다. 기존·복구 가능·백업 참조가 있거나 보존 근거가 없으면 제거하지 않는다. 제거 실패 시 `purged_at`은 NULL이다. |
| 분산 인증 제한 | 기존 PostgreSQL에서 프로세스 간 공유하는 원자적 시도 제한을 구현한다. | 10분 동안 최대 10회의 기존 제한을 유지한다. 로그인 트랜잭션 실패로 시도 수가 되돌아가지 않는다. 저장소 장애 시 메모리로 우회하지 않는다. |

스토리지 제공자와 백업 보존 증거의 실제 공급은 인프라 연결 작업이다. 미설정 상태에서 로컬 어댑터나 임의의 보존 해제값으로 운영 경로를 우회하지 않는다. 일반 사용자의 요청이나 신고 운영자 권한만으로 복구·영구 제거를 승인하지 않는다.

## 책임과 통합 순서

- 복구 작업자는 maintenance Provider·컨트롤러와 전용 테스트를 소유한다.
- 파일 작업자는 storage Provider·컨트롤러와 전용 테스트를 소유한다.
- 인증 작업자는 인증 제한 코드와 필요한 로컬 스키마·제약, 전용 테스트를 소유한다.
- 조정자는 공통 모듈 등록, 생성 코드, 격리 실행기 연결, 기존 호출부 통합, 문서와 최종 검증을 소유한다. 공유 파일의 변경은 단일 책임자가 반영한다.
- 구현 후 타입·lint·DB 없는 회귀 검사·SDK·빌드를 확인한다. 이후 새 DB에서 승인 거부, 상태 충돌, 실패 롤백, 실제 파일 동작과 다중 DB 클라이언트의 인증 제한을 검사한다.
- 실제 실행한 결과만 검증 기록에 남긴다. 로컬 복구 검사를 운영 백업·파일 복원이나 RPO·RTO 달성으로 표시하지 않는다.
