# 뜨개로그 테이블 설계

## 기준과 범위

- 기능과 DB 규칙의 기준은 [요구사항 문서](requirements.md)입니다.
- 테이블 정의의 기준은 [Prisma 스키마](../packages/backend/prisma/schema/main.prisma)입니다.
- [ERD.md](../packages/backend/docs/ERD.md)는 스키마에서 생성합니다. 직접 수정하지 않습니다.
- 2026-10-10에 승인한 구조 피드백과 확정 업무 정책을 로컬 저장 설계에 반영합니다. API 구현과 실행 검증은 별도로 진행합니다.
- 후속 API 구현과 실제 격리 PostgreSQL 검증의 현재 결과는 [구현 검증 기록](implementation-validation.md)에 있습니다. 아래의 과거 정적 검증 범위와 구분합니다.
- 업무 정책의 단일 기준은 [확정 요구사항](requirements.md#6-확정-업무-정책)입니다. 스키마의 정적 계약과 실제 업무 동작의 수용을 구분합니다.
- CHECK와 부분 고유 인덱스의 기준은 [보완 SQL](../packages/backend/prisma/design-constraints.sql)입니다. 이 파일은 승인된 마이그레이션이 아닙니다.
- 복구 목표와 서비스 재개 절차의 기준은 [데이터 복구 문서](data-recovery.md)입니다.
- 문장은 ASD-STE100의 명료성 원칙을 참고합니다. 한국어 문서의 정식 표준 준수를 뜻하지 않습니다.
- 원본 PDF는 이번 작업에서 다시 확인하지 않았습니다. 컬럼 타입과 상세 저장 방식은 아래의 설계 제안입니다.
- 로컬 스키마 작성과 문서 생성은 발주사의 DDL 반영 승인을 뜻하지 않습니다. DB에 접속하거나 DDL을 반영하지 않습니다.

## 책임과 직교성

- 모델과 컬럼은 소문자 snake_case를 사용합니다. 모델 접두어는 기존 저장소 방식에 맞춰 생략합니다.
- 모든 모델은 UUID 기본 키를 사용합니다. 자동 증가 정수와 IDENTITY는 사용하지 않습니다.
- 모든 업무 모델은 공통 감사 컬럼 4개와 deleted_at을 가집니다. 생성 시 변경 시각은 생성 시각과 같게 초기화합니다.
- created_by와 updated_by는 서버가 기록합니다. 사용자 ID 또는 system_principals에 작업 종류별로 등록한 고정 UUID를 사용합니다. 등록 행의 실제 배치와 주체 검증은 구현·운영 책임입니다.
- 시각은 timestamptz(3)로 저장합니다. 작업 시간은 정수 초로 저장합니다. 길이 제한은 초기 저장 한도이며 입력 정책의 확정을 뜻하지 않습니다.
- 방장 정보는 projects.owner_user_id만 기준으로 사용합니다. 멤버십에 같은 권한을 중복 저장하지 않습니다.
- 멤버십은 참여 기간과 접근 권한을 표현합니다. 개인 작업 데이터를 소유하지 않습니다.
- 멤버십 생성 시각은 참여 시작 시각입니다. 참여 종료는 left_at을 기록합니다. 재가입은 새 멤버십을 생성합니다.
- 유효한 멤버십은 left_at과 deleted_at이 모두 NULL인 행입니다. 사용자와 프로젝트도 삭제되지 않아야 합니다.
- 개인 작업 공간은 사용자에게 귀속됩니다. 상태와 실·바늘 메모는 작업 공간에 저장합니다.
- 초기 버전의 실·바늘 정보는 각각 텍스트 메모입니다. 구조화된 필드와 복수 항목 모델은 초기 버전에서 제외합니다.
- 카운터와 기록은 workspace_id로 작업 공간을 참조합니다. 기록에 프로젝트 ID를 중복 저장하지 않습니다.
- 같은 프로젝트와 사용자의 작업 공간은 하나만 유지합니다. 삭제된 작업 공간의 자리를 새 행으로 대체하지 않습니다.
- 기록의 author_id는 원 작성자입니다. 신규 개인 기록은 작업 공간 소유자와 작성자의 일치를 검사합니다.
- 이관은 작업 공간의 project_id만 변경합니다. 작업 공간의 owner_user_id는 변경하지 않습니다.
- 기록 작성자와 댓글·반응 작성자는 별도로 보존합니다. 이관 시 다른 작성자의 식별자나 소유권을 변경하지 않습니다.
- 친구 관계는 정렬한 사용자 쌍으로 저장합니다. 차단은 방향별로 저장하며 조회 시 양쪽 방향을 확인합니다.
- 친구·차단·좋아요·반응의 고유 관계는 해제 뒤 같은 행을 재사용합니다. 재활성화는 해당 관계의 업무 명령으로만 수행합니다.
- 동의 이력과 처리한 요청은 별도 행으로 보존합니다. 공통 감사 컬럼은 이전 내용의 변경 이력을 대신하지 않습니다.
- 신고 대상은 사용자 또는 게시글 중 하나로 제안합니다. 신고 후 선택적 차단은 같은 비즈니스 작업에서 처리하며 신고 테이블에 차단 상태를 중복 저장하지 않습니다.
- 프로필 통계와 총 시간은 기록에서 계산합니다. 저장된 집계 값을 추가하지 않습니다.

## 이관과 역이관

1. 서버는 이관 작업 UUID와 요청 내용을 확인합니다.
2. 서버는 공통 잠금 순서로 대상 행을 잠급니다.
3. 서버는 현재 소유권과 참여 권한을 다시 검증합니다.
4. 서버는 개인 프로젝트와 새 멤버십을 생성합니다.
5. 서버는 기존 멤버십의 left_at을 기록합니다.
6. 서버는 작업 공간의 project_id를 변경합니다.
7. 서버는 작업 공간의 version을 증가시킵니다.
8. 서버는 workspace_transfers에 변경 전후 관계와 증가한 version을 기록합니다.
9. 서버는 요구사항의 대기 초대 정리를 같은 트랜잭션에서 수행합니다.
10. 서버는 트랜잭션을 커밋한 뒤 새 프로젝트 ID를 반환합니다.

- 방장은 같은 트랜잭션에서 직접 지정한 유효한 후임 멤버에게 방장 권한을 양도합니다. 다른 멤버가 있는데 후임을 지정하지 않으면 종료를 거부합니다. 혼자 남은 프로젝트는 종료합니다.
- 이관은 하위 카운터, 기록, 댓글과 반응의 행을 복사하지 않습니다. 식별자와 원 작성자를 유지합니다.
- project_timers는 작업 공간과 소유자를 참조합니다. 이관은 타이머 UUID와 소유자·누적 시간을 변경하지 않습니다. 현재 실행 구간과 일시정지 상태도 보존합니다.
- workspace_transfers.id는 이관 작업 식별자입니다. 재시도는 같은 식별자를 사용합니다.
- 기존 작업 식별자가 있으면 처리 주체와 요청 내용을 비교합니다. 일치하면 기존 결과를 반환합니다. 불일치하면 거부합니다.
- 작업 식별자 비교는 일반 업무 필터로 이력을 제외하지 않습니다. 권한 없는 주체에게 기존 결과를 반환하지 않습니다.
- 이관 완료 시각과 처리 주체는 이력의 created_at과 created_by입니다. 업무 필드는 생성 후 변경하지 않습니다.
- 작업 공간과 하위 데이터의 모든 변경은 작업 공간을 잠급니다. 같은 트랜잭션에서 version을 증가시킵니다.
- 역이관은 별도 승인을 받습니다. 현재 프로젝트와 version이 원 이관 결과와 일치해야 합니다.
- 이후 변경이 있으면 자동 역이관을 거부합니다. 현재 데이터에 대한 별도 이관 결정을 받습니다.
- 역이관도 현재 권한과 고유 제약을 검증합니다. 새 이관 이력을 생성합니다. 기존 이력을 덮어쓰지 않습니다.
- 이관 후 접근은 현재 귀속 프로젝트의 유효한 참여와 차단 상태로 판단합니다. 이전 참여와 댓글 작성 사실만으로 접근을 허용하지 않습니다.

## 삭제와 복구 경계

| 대상 | 업무 종료 또는 삭제 표시 | 콘텐츠 복구 처리 |
|---|---|---|
| 프로젝트·작업 공간·카운터·기록·댓글·게시글 | 직접 삭제한 행에 deleted_at과 deletion_operation_id를 함께 기록합니다. | 승인한 삭제 작업의 현재 대상만 복구합니다. |
| 프로젝트 참여 | left_at으로 참여를 종료합니다. | 콘텐츠 복구로 참여를 재개하지 않습니다. 재가입은 새 행입니다. |
| 친구·차단·좋아요·반응 | deleted_at으로 관계 해제를 표시합니다. | 콘텐츠 복구에서 제외합니다. 별도 업무 명령을 사용합니다. |
| 계정·세션 | 탈퇴 시 인증을 차단하고 공개 프로필·인증 비밀값을 제거합니다. | 콘텐츠 복구에서 제외합니다. 탈퇴한 계정은 복구하지 않습니다. |
| 타이머·복구 코드·명령 결과·식별자 예약 | 상태 전환과 무효화·완료 결과·예약을 각각 보존합니다. | 콘텐츠 복구로 실행 상태·인증 수단·완료 명령·예약을 되돌리지 않습니다. |
| 이관 이력·정책 동의·신고 증거 | 별도 보존 정책을 적용합니다. | 일반 콘텐츠 복구에서 제외합니다. |
| 저장 객체 | deleted_at으로 신규 참조를 금지합니다. purged_at으로 실제 제거를 확인합니다. | 파일 복구 검증을 별도로 수행합니다. |

- 부모 삭제는 자식 행의 deleted_at과 deletion_operation_id를 변경하지 않습니다.
- 기록 조회는 기록, 작업 공간과 프로젝트의 삭제 상태를 확인합니다. 댓글과 반응 조회도 같은 상위 경로를 확인합니다.
- 게시글 댓글과 좋아요 조회는 게시글의 삭제 상태를 확인합니다. 각 조회는 현재 사용자와 차단 정책도 적용합니다.
- 부모 복구는 이미 직접 삭제한 자식 콘텐츠를 복구하지 않습니다.
- 여러 콘텐츠를 직접 삭제하는 작업은 같은 삭제 작업 UUID를 기록합니다. 이미 삭제된 행의 작업 UUID를 덮어쓰지 않습니다.
- 복구 대상은 작업 UUID와 승인한 행 목록으로 고정합니다. 새로 삭제된 행을 자동으로 대상에 추가하지 않습니다.
- 복구는 대상과 부모를 잠근 뒤 현재 소유권, 삭제 작업 UUID와 고유 제약을 다시 확인합니다.
- 복구는 부모부터 처리합니다. 대상의 deleted_at과 deletion_operation_id를 함께 NULL로 변경합니다.
- 복구는 삭제된 부모 아래에 유효한 자식을 단독으로 노출하지 않습니다. 필요한 부모 복구 승인이 없으면 거부합니다.
- 감사 컬럼은 최근 변경만 기록합니다. 삭제·복구 작업의 승인 대상과 처리 결과는 운영 기록으로 보존합니다.

## 증거와 저장 객체

- 정책 문서의 새 내용은 새 버전으로 저장합니다. 동의가 참조한 문서의 제목과 본문은 변경하지 않습니다.
- 신고 대상의 존재와 접근 권한은 접수 트랜잭션에서 검증합니다. 검증한 대상에서 증거를 생성합니다.
- reports.target_snapshot은 서버가 허용한 텍스트 필드만 저장합니다. 원본 사용자 행을 통째로 직렬화하지 않습니다.
- 증거 캡처 시각은 reports.created_at입니다. 신고 대상의 변경과 삭제는 증거를 변경하지 않습니다.

| 신고 대상 | target_snapshot의 허용 필드 |
|---|---|
| 사용자 | schema_version=1, handle, nickname, biography, source_updated_at |
| 게시글 | schema_version=1, author_id, body, source_updated_at |

- source_updated_at은 캡처한 원본의 updated_at입니다. 시각은 UTC ISO 8601 문자열로 저장합니다.
- 사용자 biography의 NULL을 보존합니다. 필드 누락과 NULL을 같은 의미로 취급하지 않습니다.
- 신고 증거는 비밀번호, 세션, 토큰과 로그인 ID를 포함하지 않습니다. JSON 형식과 대상 종류의 일치는 비즈니스 계층에서 검증합니다.
- 초기 버전의 신고 증거는 텍스트입니다. 사진 증거의 별도 사본은 초기 버전에서 제외합니다.
- stored_objects는 서비스 관리 파일을 참조합니다. 프로필 사진과 프로젝트 대표 사진은 저장 객체 ID를 저장합니다.
- owner_user_id는 파일의 최초 소유자입니다. created_by와 updated_by는 파일 사용 권한의 기준이 아닙니다.
- 신규 참조는 파일 소유자이거나 현재 접근 가능한 원본 프로젝트의 사진을 이관하는 경우에만 허용합니다. 대상 프로젝트의 쓰기 권한도 확인합니다.
- 이관은 파일 소유자를 변경하지 않습니다. 소유자 탈퇴만으로 다른 프로젝트가 참조하는 파일을 제거하지 않습니다.
- 저장 위치는 승인된 storage_code로 식별합니다. 저장 위치 코드가 가리키는 저장소를 임의로 교체하지 않습니다.
- object_key는 저장 위치 안에서 재사용하지 않습니다. 같은 객체의 바이트를 덮어쓰지 않습니다.
- sha256과 byte_size는 파일 복원 결과를 검증하는 기준입니다. URL과 인증 정보는 저장하지 않습니다.
- 신규 파일 참조와 파일 제거 준비는 같은 저장 객체 행을 잠급니다. 참조 추가는 deleted_at이 NULL인 객체만 허용합니다.
- 파일 제거 준비는 계정과 프로젝트의 전체 참조를 검사합니다. 삭제된 콘텐츠의 복구 가능 기간도 검사합니다.
- 이관 프로젝트의 대표 사진은 원 프로젝트와 같은 객체를 참조할 수 있습니다. 원 프로젝트 삭제만으로 파일을 제거하지 않습니다.
- 제거 준비는 참조 검증 후 deleted_at을 기록합니다. 이후 신규 참조와 일반 콘텐츠 복구를 차단합니다.
- 실제 파일 제거는 외부 작업입니다. 제거 실패 시 purged_at을 기록하지 않습니다. 재시도는 같은 객체 키의 존재를 확인합니다.
- 삭제된 콘텐츠의 참조를 포함한 모든 보존 조건이 충족돼야 파일을 제거합니다. 계정 사진의 보존 조건은 탈퇴 정책과 함께 확정합니다.

## 물리 FK와 비즈니스 책임

- relationMode = "prisma"를 사용합니다. @relation은 논리 관계와 ERD를 위한 선언입니다.
- 생성된 ERD의 FK 표시는 참조 컬럼을 뜻합니다. PostgreSQL FOREIGN KEY 제약이 있다는 뜻이 아닙니다.
- relationMode 변경만으로 관계 무결성을 보장하지 않습니다. 생성, 일괄 쓰기와 raw SQL을 포함한 모든 쓰기 경로에서 요구사항 DB-FK-001~009를 적용해야 합니다.
- 관계 컬럼의 조회 인덱스를 명시합니다. 기본 키와 고유 제약·인덱스는 pk_와 ux_ 접두어를 사용합니다.
- 논리 관계에는 Restrict를 명시합니다. 자동 삭제나 연쇄 변경은 선언하지 않습니다. 물리삭제는 복구 기간 만료, 현재 참조 부재와 이력 보존 조건을 모두 확인합니다. 실제 정리 도구는 별도로 검증합니다.
- Restrict는 Prisma 경로의 보조 동작입니다. 논리삭제 검사, 소유권 검사, 트랜잭션과 동시성 제어를 대신하지 않습니다.
- 방장의 유효한 멤버십, 기본 카운터 2개와 작업 공간 소유권은 비즈니스 계층에서 보장합니다.
- Prisma 생성 SQL만으로 CHECK와 부분 고유 인덱스가 반영되지는 않습니다. 보완 SQL을 검토된 마이그레이션에 포함해야 합니다.
- Prisma의 partialIndexes는 Preview 기능입니다. 이번 설계는 해당 기능을 활성화하지 않고 보완 SQL을 사용합니다.

| DB 보장 | 정의 위치 |
|---|---|
| PK·전체 행 고유 키·NOT NULL·일반 조회 인덱스 | Prisma 스키마 |
| 음수 금지·done과 종료 시각 일치·친구 쌍 정렬·자기 관계 금지 | 보완 SQL의 CHECK |
| 신고 대상 단일 선택·이관 전후 관계 구분·파일 무결성 값 형식 | 보완 SQL의 CHECK |
| 직접 삭제 시각과 삭제 작업 UUID의 동시 존재 | 보완 SQL의 CHECK |
| 탈퇴 시 공개 프로필·인증 해시 제거, 식별자 형식, 명령 입력 해시 | 보완 SQL의 CHECK |
| 타이머 상태·시작 시각·종료 기록 일치, 카운터 변경 번호·표시 순서 | 보완 SQL의 CHECK |
| 신고 other의 상세 내용, 종결 상태·시각 일치 | 보완 SQL의 CHECK |
| 유효한 멤버십 한 개 | left_at과 deleted_at이 NULL인 행의 부분 고유 인덱스 |
| 사용자 쌍의 양방향 대기 친구 요청 한 개 | LEAST·GREATEST 사용자 쌍의 부분 고유 인덱스 |
| 프로젝트와 수신자의 대기 초대 한 개 | pending이며 deleted_at이 NULL인 행의 부분 고유 인덱스 |
| 작업 공간의 미종료 타이머 한 개 | running 또는 paused이며 deleted_at이 NULL인 행의 부분 고유 인덱스 |

### 잠금 순서

- 잠금 순서는 users, stored_objects, projects, project_memberships, project_workspaces 순서입니다.
- 하위 잠금 순서는 project_timers, project_records, project_counters, record_comments, record_reactions 순서입니다.
- 커뮤니티 잠금 순서는 posts, post_comments, post_likes, reports, report_actions 순서입니다. 공통 상위 잠금 뒤에 수행합니다.
- 계정 식별자·복구 코드·세션과 명령 결과는 관련 users 잠금 아래에서 처리합니다. 계정 행이 아직 없으면 식별자 고유 제약으로 경합을 거부합니다.
- 친구·차단·초대의 쓰기는 관련 사용자 행을 UUID 오름차순으로 먼저 잠급니다. 같은 테이블의 여러 행도 UUID 오름차순으로 잠급니다.
- 각 작업은 필요한 행만 잠급니다. 아직 없는 멤버십과 요청은 상위 사용자·프로젝트 잠금과 고유 인덱스로 보호합니다.
- 삭제, 이관, 하위 데이터 쓰기와 복구는 같은 순서를 사용합니다. 잠금 후 최신 관계와 권한을 확인합니다.
- 대상 탐색 후 필요한 잠금 집합이 바뀌면 트랜잭션을 중단합니다. 변경된 집합으로 처음부터 다시 검증합니다.
- 데드락과 직렬화 충돌은 해당 트랜잭션을 롤백합니다. 외부 파일 작업을 DB 재시도에 함께 반복하지 않습니다.

### 논리 관계의 처리 책임

| 관계 | 쓰기 검증 | 대상 종료·삭제 시 처리 |
|---|---|---|
| 세션·동의·친구·차단 → 사용자 | 현재 계정과 업무 권한을 확인합니다. | 세션을 무효화합니다. 관계 해제와 보존은 탈퇴 정책을 적용합니다. |
| 동의 → 정책 문서 | 대상 버전과 본문 불변 규칙을 확인합니다. | 동의가 참조한 버전을 보존합니다. |
| 프로젝트 → 방장 | 유효한 멤버십을 확인합니다. | 후임 결정 없이 방장 참여를 종료하지 않습니다. |
| 멤버십·초대 → 프로젝트·사용자 | 프로젝트, 계정과 현재 참여 권한을 확인합니다. | 접근을 차단합니다. 종료한 참여 기간을 보존합니다. |
| 작업 공간 → 프로젝트·사용자 | 현재 소유자의 유효한 멤버십을 확인합니다. | 프로젝트 삭제는 작업 공간을 수정하지 않습니다. 이관은 귀속만 변경합니다. |
| 카운터·기록 → 작업 공간 | 소유자, 부모 상태와 작업 상태를 확인합니다. | 부모 삭제 시 노출을 차단합니다. 이관 시 식별자를 유지합니다. |
| 기록·댓글·게시글 → 작성자 | 작성자와 현재 쓰기 권한을 확인합니다. | 필요한 원 작성자 식별자를 보존합니다. 탈퇴 후에는 `탈퇴한 사용자`로 표시합니다. |
| 기록 댓글·반응 → 기록 | 상위 프로젝트와 현재 접근 권한을 확인합니다. | 기록과 함께 보존합니다. 별도 삭제된 행은 복구하지 않습니다. |
| 게시글 댓글·좋아요 → 게시글 | 게시글 상태와 차단 관계를 확인합니다. | 부모 삭제 시 노출을 차단합니다. 좋아요를 자동 재활성화하지 않습니다. |
| 신고 → 신고자·대상 | 대상 단일 선택과 접근 권한을 확인합니다. | 대상 참조와 접수 당시 증거를 보존합니다. |
| 이관 이력 → 작업 공간·프로젝트·참여 기간 | 변경 전후 관계와 작업 식별자를 확인합니다. | 일반 콘텐츠 삭제와 복구에서 제외합니다. |
| 계정·프로젝트 → 저장 객체 | 객체 존재, 제거 상태와 참조 권한을 확인합니다. | 현재 참조와 복구 보존 조건을 검사한 뒤 파일을 제거합니다. |
| 저장 객체 → 최초 소유자 | 파일 등록 시 현재 소유자를 확인합니다. 감사 주체로 권한을 추정하지 않습니다. | 소유자 식별자를 보존합니다. 다른 유효한 참조가 있으면 파일을 유지합니다. |

복구와 일괄 입력에도 같은 관계 규칙을 적용합니다. FK가 없다는 이유로 고아 참조를 허용하지 않습니다.

## 확정 요구사항의 설계 반영 범위

정책의 단일 기준은 [요구사항 문서 6절](requirements.md#6-확정-업무-정책)입니다. API 버저닝은 [요구사항 문서 7절](requirements.md#7-api-버저닝)을 따릅니다. 아래 저장 계약은 스키마에 반영했습니다. API와 실제 트랜잭션 수용은 별도 증거가 필요합니다.

| 확정 정책 | 저장 계약 | 업무 검증 책임 |
|---|---|---|
| 서버 타이머·기기 간 이어하기 | project_timers의 status, started_at, accumulated_seconds, version, stopped_at, record_id | 서버 시각으로 누적 시간 계산, done 전환 거부, 종료와 기록 생성의 원자성 |
| 명령 중복 방지 | command_receipts의 작업 UUID, actor_user_id, command_type, request_hash, result | 같은 트랜잭션의 완료 결과 저장, 다른 입력·주체의 재사용 거부, 비밀값 제외 |
| 카운터 표시와 충돌 | project_counters의 is_visible, sort_order, version | 원자적 증감, 기대 version 확인, 같은 작업 공간의 순서만 변경 |
| 계정 복구·토큰 폐기 | recovery_codes의 해시·사용·폐기 시각, users.auth_version, auth_sessions의 접근·갱신 토큰 해시와 각 만료 시각 | 일회 사용·재발급 원자성, 탈퇴·재설정 후 현재 세션 확인 |
| 식별자 영구 예약 | user_identifiers의 kind와 value 고유 키, 변경 불가 login_id | 과거 handle의 다른 계정 발급 거부, 원래 계정의 복귀 확인 |
| 탈퇴 후 식별자 보존 | users의 선택적 handle·nickname·password_hash와 보완 SQL의 제거 CHECK | 공개 프로필·비밀값 제거, 관계·이관 이력 유지, 후임 처리 실패 롤백 |
| 정책 활성 버전·재동의 | language=ko, effective_at, requires_reconsent, 종류별 버전·효력 시각 고유 키 | 효력 시작 시각이 지난 최신 버전 선택, 참조 본문 불변, 업무 변경 거부 |
| 시스템 감사 주체 | system_principals의 고정 UUID와 작업 code 고유 키 | 등록된 서버 주체 선택, 클라이언트 지정 거부 |
| 프로젝트 종료 | projects.terminated_at | 후임 지정 검사, 20명 상한, 종료 후 신규 참여·쓰기 거부 |
| 신고와 조치 | reports의 사유 enum·status·closed_at, report_actions의 조치·reason·result·감사 주체 | 제한된 운영자 권한, 증거 불변, 조치 이력 수정 금지 |
| 기록 반응 코드 | e_reaction_code의 확정 코드 5개 | 현재 귀속 참여·차단·부모 삭제 상태 확인 |

다음 항목은 저장 계약과 별도로 구현·검증합니다.
- 프로젝트 인원 상한, 방장 종료, 차단 우선 조회와 done 상태별 허용 작업을 비즈니스 계층에 구현해야 합니다.
- 탈퇴 시 비밀값 제거와 참조 식별자 보존을 같은 트랜잭션에서 처리해야 합니다.
- 확정한 입력 규칙과 코드 목록을 API 검증에 반영해야 합니다.
- 초기 버전에서 제외한 게시글 수정·사진 신고 증거·구조화된 실·바늘 모델은 추가하지 않습니다.
- [복구 운영 결정](data-recovery.md#운영-결정)의 목표는 실제 복원으로 검증해야 합니다. 정책 확정은 운영 수용 완료를 뜻하지 않습니다.

## 생성과 검증

```sh
# 요구사항 ERD만 검증하고 생성합니다.
pnpm build:erd

# 뜨개로그 Prisma 클라이언트와 요구사항 ERD를 생성합니다.
pnpm -C packages/backend build:prisma

# 실제 DB를 읽거나 변경하지 않고 생성 SQL을 확인합니다.
pnpm -C packages/backend exec prisma migrate diff --from-empty --to-schema prisma/schema --script

# 모델·관계·감사 컬럼·보완 SQL·생성 SQL의 FK 부재를 검증합니다.
pnpm -C packages/backend check:erd
```

Prisma 클라이언트의 출력 경로는 packages/backend/src/prisma입니다. 기존 공통 유틸리티와 모니터 API는 유지합니다.

검증 범위는 스키마 문법, 생성 문서, 객체 명명, 설계 계약과 생성 SQL의 FK 부재입니다. 보완 SQL은 정적으로 검사합니다. 실제 PostgreSQL의 제약 실행, 동시성, 관계 검증 API와 복구는 검증 범위에 포함하지 않습니다.

## 구현 수용 시나리오

| 시나리오 | 필요한 결과 |
|---|---|
| 동시 양방향 친구 요청·동시 프로젝트 초대 | 유효한 대기 요청을 하나만 생성합니다. |
| 동시 수락·나가기·새 기록 생성 | 종료한 참여 권한으로 새 데이터를 생성하지 않습니다. |
| 이관 단계별 실패 | 프로젝트·참여·작업 공간·이력의 변경을 모두 롤백합니다. |
| 같은 이관 작업의 재시도 | 기존 결과를 반환합니다. 프로젝트와 이력을 중복 생성하지 않습니다. |
| 같은 작업 식별자와 다른 입력 | 요청을 거부합니다. 기존 결과를 노출하지 않습니다. |
| 나가기·재가입·반복 나가기 | 참여 기간별 행을 보존합니다. 카운터·기록·댓글 식별자를 유지합니다. |
